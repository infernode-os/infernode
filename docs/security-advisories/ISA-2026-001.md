## Summary

The emulator's path names (`Cname`) were Plan 9's pre-Fourth-Edition
form, a bare string, and `undomount` reversed a bind by comparing that
string with the mount table. In a name space Veltro had restricted, the
comparison never matched the shadow directory a grant was bound onto,
so `..` from inside a granted directory walked to the real parent.
Two parent walks out of any bound-in entry reached the emulator's root:
`/dis/lib/../..` was the project root, readable and writable, and a
shell reached it through a redirection alone. Relative walks from the
working directory escaped the same way. The fault is inherited from
upstream Inferno.

In the same change, `task create` naming tools or paths a parent could
not delegate dropped the refused grants and started the child anyway,
on the whole delegation budget when nothing was left: delegation added
authority instead of narrowing it.

## Impact

An agent granted only `read` and `list`, steered by a model or by text
it read, could read any file under the emulator root and create or
replace files there, including the Dis bytecode and profile the next
boot runs. A delegated child could hold tools (`write`, `edit`, `exec`)
its parent did not.

## Fix

The Fourth Edition path structure is ported: a name carries the mount
points it crossed, `undomount` pops the recorded channel, and the walk's
origin is pinned, so no number of `..` elements rises above it. A child
whose requested grant includes anything its parent cannot delegate is
refused, and an omitted `tools=` means the read-only baseline. The
native kernel took the same port in 0.5.0 (`ce477538d`).

## Workarounds

None. Update to 0.4.0 or later; do not run agents with tools on
releases before it.

Found by the project's red-team campaign (INFR-405, INFR-407).
