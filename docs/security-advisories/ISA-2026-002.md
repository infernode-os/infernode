## Summary

Veltro gave an agent read-only views of code, libraries, metadata and
source, but nothing in the kernel made a bind read-only: the view was
the directory itself, and a tool that could write reached it. A red-team
campaign overwrote `sh.dis` this way. The restriction was also lost when
the view was exported over 9P and mounted again.

## Impact

An agent with a write-capable tool could replace bytecode that the
system and other agents run, including the shell, which persists past
the session and runs with the user's authority.

## Fix

A new mount flag, `MREADONLY`, attenuates a bind: creates, writes,
removes and wstats through it are refused, the restriction survives
rebinds and 9P exports, and Veltro's code, library, metadata and source
views use it.

## Workarounds

None. Update to 0.4.0 or later.

Found by the project's red-team campaign (INFR-453).
