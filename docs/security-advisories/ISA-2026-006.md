## Summary

A 9P wstat leaves mode and times alone by sending all ones in their
32 bits. `convM2D` stored that in `Dir`'s `ulong` fields, which are 64
bits on Linux and macOS, so no "don't change" test matched. `mv` inside
InferNode (in the shell, Xenith or an agent's tool) left the host file
mode 777 with a modification time in 2106, and `chmod` set that time
too. Pipes and other devices took the same path. Windows, where `ulong`
is 32 bits, was not affected.

## Impact

Files renamed through InferNode on a shared Linux or macOS host became
writable by every other user of the host.

## Fix

An all-ones 32-bit mode or time is kept as the whole field's "don't
change", in lib9 (the emulator) and libkern (the native kernel).

## Workarounds

On an affected release, check the modes of host files renamed through
InferNode (`find ... -perm -0002`) and correct them. Update to 0.6.0 or
later.
