## Summary

ML-DSA's Decompose divided by `2*gamma2` on values derived from the
secret key (`LowBits(w - c*s2)` and the hints over `c*t0`). A hardware
divide's time depends on its operands, and the shipped Linux/amd64 and
Android/arm64 builds had divide instructions in `decompose`,
`highbits`, `lowbits` and `makehint`. This is the leak reported in
another implementation as CVE-2026-22705.

## Impact

Someone able to time many ML-DSA signatures (an authentication server
signing in reply to connections, for instance) could learn information
about the signing key.

## Fix

Decompose multiplies by a fixed-point reciprocal, as the reference
implementation does, with no division and no branch on the value.
Signatures are unchanged. A host test fails if a divide instruction
appears in it at any optimisation level.

## Workarounds

None. Update to 0.6.0 or later. ML-DSA signing changed again in 0.11.0
to follow FIPS 204 exactly; certificates made before that are refused
and must be issued again.

Found internally.
