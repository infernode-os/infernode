Title: Release packages shipped a private key shared by every install
Severity: high
CWE: CWE-321 CWE-798
Affected: < 0.9.0
Patched: 0.9.0
Commits: a02079cca
Changelog: 0.9.0
GHSA:
CVE:

## Summary

Every release package carried `usr/inferno/keyring/default`, an ed25519
private key for the owner `testnode`, committed to this public
repository as a test fixture. `listen`, `styxlisten`, `mount`, `dial`,
`cpu` and `rcmd` use `/usr/<user>/keyring/default` when no key is named,
so every install made from a release held the same private key.

## Impact

On an install that authenticated with the default key, anyone with this
repository could authenticate as that install, or as a peer it trusts by
that key: mount its exports, run commands through `cpu` or `rcmd`, or
pose as its server.

## Fix

Every package job empties each `usr/*/keyring/` and refuses the package
if an Inferno or PEM private key is left anywhere in it, and a CI test
fails if a job does not.

## Workarounds

On an install made from a release before 0.9.0, delete
`usr/inferno/keyring/default` (and any copy of it), make keys of your
own (`auth/createsignerkey`, `getauthinfo`), and stop trusting
`testnode` anywhere it was accepted. Updating alone does not remove a
key already installed.

Found internally.
