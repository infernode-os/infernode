## Summary

The bare-metal kernel's IP stack (`os/ip`), inherited from Inferno,
took several lengths from received packets without comparing them with
what arrived:

- IPv4 reassembly trusted each fragment's offsets and total length, so
  a fragment could claim bytes that were never received, and the
  assembled extent had no cap;
- a UDP length shorter than the UDP header, a TCP data offset longer
  than the IP payload, and truncated ICMPv6 neighbor solicitations and
  advertisements were indexed and trimmed as they claimed;
- TCP's out-of-order queue had no bound in bytes or in blocks.

Bell Labs Plan 9 has the same reassembly fault; 9front fixed these
over 2013-2019, and the fixes are ported from it.

## Impact

Anyone who can send packets to a board running the native kernel
(Raspberry Pi, QEMU virt, PolarFire), with no authentication, could
make the kernel read past its buffers, hand ICMP, TCP and UDP data that
was never received, or exhaust its memory. The hosted emulator uses the
host's IP stack and was not affected.

## Fix

Fragments are checked and trimmed to the IPv4 total length and the
bytes received, alignment is checked and the assembled size capped;
transport and ICMPv6 lengths are checked before any indexed access; the
TCP resequencing queue is bounded by the receive window and a count of
blocks. 0.11.0 extended the same checks through the rest of the stack
(ARP, ICMP, IPv6 extension headers and reassembly, TCP options).

## Workarounds

Keep native-kernel boards on a network you control, wired, as the
documentation advises. Update to 0.10.0 or later (0.11.0 or later for
the rest of the stack).
