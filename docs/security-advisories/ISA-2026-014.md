## Summary

The agent's `xenith` tool opens and drives Xenith windows, and Xenith
reads and writes a window's file in its own, unrestricted name space.
The tool's `create` took any name and its `ctl` passed any command to a
window the agent owned, so `create`, a body write, `ctl name <path>` and
`put` wrote any file Xenith could reach, and `get` read one. A body
read of another window was allowed when the window's directory was in
the agent's name space, which the directories above a grant always
are.

## Impact

An agent with the xenith tool could read and write files outside every
grant it held, with the user's authority. A window named after a file
was also one the user's own `Put` or `Putall` would write.

## Fix

`create` takes a label (the window is `/+label`); `ctl` takes layout and
display commands only (`name`, `get`, `put`, `dump` and the rest are
refused); another window's body is readable only for `+Errors`.

## Workarounds

Do not give agents the xenith tool on a release before 0.10.0.

Found by the project's security review.
