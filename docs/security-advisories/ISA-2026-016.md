## Summary

- P-256 and P-384 (`libsec/ecc.c`) reduced every product through libmp,
  whose time depends on its operands; point addition and doubling
  branched on the identity, so the ladder showed a scalar's leading
  zeros; ECDSA inverted its nonce with a variable-time extended GCD.
- secp256k1 had the same faults, and computed signatures with the
  private key through libmp.
- `mpexp`, under `IPint.expmod` and so every Inferno-auth
  Diffie-Hellman (login, logind, factotum) and secstore, was binary
  square-and-multiply, branching on each bit of the secret exponent.

## Impact

Someone who could time many operations (a server answering
connections, a signer, a wallet signing transactions) could learn
private scalars, ECDSA nonces or Diffie-Hellman exponents.

## Fix

P-256, P-384 and secp256k1 use Montgomery arithmetic, complete addition
formulas and a fixed window with masked table reads, and invert by
Fermat; `mpexp` uses a Montgomery fixed window for odd moduli. A
valgrind constant-time check (ctgrind) of each runs in CI.

## Workarounds

None. Update to 0.10.0 or later.
