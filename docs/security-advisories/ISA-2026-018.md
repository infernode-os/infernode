Title: AES-GCM's GHASH used secret-indexed table lookups
Severity: low
CWE: CWE-208
Affected: < 0.10.1
Patched: 0.10.1
Commits: 3bce4a5e1
Changelog: 0.10.1
GHSA:
CVE:

## Summary

GHASH looked up a table by nibbles of the running hash, which depends
on the key and the data. A cache shared with an attacker shows which
entries were read.

## Impact

A process sharing a CPU cache with InferNode (another program on the
host, or another tenant) could in principle learn about the GCM hash
key, and from it forge records of AES-GCM connections (TLS).

## Fix

GHASH uses PMULL where the processor has it and otherwise an integer
multiplication that indexes nothing (after BearSSL); a valgrind
constant-time check runs in CI. 0.12.0 adds x86-64's PCLMULQDQ.

## Workarounds

None. Update to 0.10.1 or later.

Found internally.
