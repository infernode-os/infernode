## Summary

The git library joined ref names and tree entry names to `.git` and the
work tree as they were. A remote advertising
`refs/heads/../../../../x` had `x` written outside `.git` on fetch; a
tree entry `..`, a name with a slash or `.git` was checked out where
its author chose, including into git's own directory (its config names
where pushes go); a symbolic ref `ref: ../../x` was read from outside.
The tool's worker keeps the name space from before the agent's
restriction.

## Impact

Fetching from, or checking out, a repository someone else controls
wrote files anywhere the user could write, beyond every grant of the
agent that ran the tool. `git` was in the default delegation budget.

## Fix

Ref names must be what `git check-ref-format` allows, under `refs/`;
tree entry names are one component and never `.`, `..` or what a host
reads as `.git`, checked where trees are read and again at checkout;
symbolic refs are followed to a bounded depth inside the repository.
`git` is no longer in the default delegation budget.

## Workarounds

On a release before 0.11.0, do not let an agent fetch or check out a
repository you do not control.

Found by the project's security review.
