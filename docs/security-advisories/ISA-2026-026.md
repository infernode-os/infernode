## Summary

Charon reads `file:` addresses, and names with no scheme, from its own
name space as the user who runs it, and it went wherever the page it
showed said: a link to `file:///usr/someone/notes` on a page from the
network, followed, made the file the next page. A form's action, a meta
refresh and a script's navigation did the same with nobody asking, and
a frame drew the file. `<base href="file:///dir/">` made a page claim
that address as its own.

## Impact

A web page could display, and through its scripts read, any text file
the user can read. An agent holding only the `charon` tool could read
such files by having a page link to them (`follow`, then `read body`).
Xenith's browser windows use the same engine and were affected too.

## Fix

One rule (`Page->mayload`): a document from the network may load only
network, `data:` and `about:` addresses, applied where a page moves the
session (links, forms, refresh, scripts) and where anything is fetched
for it (frames, style sheets, fonts, images). What the user asks for by
name is not restricted. `<base>` changes relative URLs only.

## Workarounds

On a release before 0.11.0, browse untrusted sites only in a name
space that holds no private files.

Found by the project's security review.
