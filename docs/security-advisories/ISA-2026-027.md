## Summary

The agent's fetch tools (`webfetch`, `http`, `browse`) ask `publicnet`
whether a destination is public and dial it as given. The check read
each part of an IPv4 address as decimal; the kernel's parser takes C's
bases. `0177.0.0.1` was 177.0.0.1 (public) to the check and 127.0.0.1
to the kernel. A host of digits the check could not parse, such as
`0177.0.0.018`, was let by.

## Impact

A model's URL, or a redirect from any public page, reached services
bound to the loopback (often their only access control), and the `http`
tool could POST to them.

## Fix

An address is accepted only as four decimal numbers with no leading
zero, the one form both read alike; any other host made of digits is
blocked.

## Workarounds

On a release before 0.11.0, do not run services on the loopback that
trust it while agents have fetch tools.

Found by the project's security review.
