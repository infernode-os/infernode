## Summary

sys-pctl(2): `NEWNS` puts the process in a new name space whose root is
its current directory. The new root was given a name of its own, so
`/..` stayed there, but the new current directory kept the name it had
before, with the mount points crossed on the way to it. A relative walk
starts from that, so `../x` opened a file of the directory above the new
root, `create ../x` made one there and `chdir("..")` went there, with
`NODEVS` or without; a second `chdir("..")` reached the root device.
Both the hosted and the native kernel.

## Impact

A program confined with `pctl(NEWNS)` (with or without `NODEVS`) could
read and write outside the directory it was confined to, by relative
names.

## Fix

The new current directory gets a fresh name, `/`, as the new root does,
so walks from it are pinned there; `pwd` after `pctl(NEWNS)` is `/`. The
fix is on `master` and in no release yet: the `v0.12.0` tag predates it,
although CHANGELOG.md lists it under 0.12.0.

## Workarounds

Until a release has the fix, confine an untrusted program as httpd(8)
does instead of with `NEWNS` alone: `FORKNS`, bind the directory over `/`
with `MREPL`, `chdir("/")`, then `NODEVS` (`tests/httpd_confine_test.b`
checks that shape). Or build from `master`.
