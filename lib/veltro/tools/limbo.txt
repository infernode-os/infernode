limbo - Author a complete, compilable Limbo source file.

  WHEN TO CALL
    Call ONLY when the user has explicitly asked you to write, author,
    create, generate, port, or "give me" Limbo code (.b files, Inferno
    modules, code that must compile on Inferno).

    DO NOT call on:
      - greetings ("hello", "hi", "hey")
      - questions about how something works
      - any message that does not contain an explicit authoring directive

  ARGS
    A single short natural-language sentence describing the program.
    Plain English only. Pass the user's request verbatim if it already
    describes the program; otherwise paraphrase in one sentence.

    args MUST NOT contain code tokens: { } ; "implement" "import"
    "include" "package main" "def main" "#include".

  RETURNS
    The Limbo source code in a single ```limbo fenced block, then a
    <gate> block saying whether it compiled (status: compiled), did not
    (status: failed, with the compiler's errors), or was not checked.

  CHECKING A FILE
    limbo compile <absolute path of a .b file>
    compiles a Limbo file you already have (written, edited, been given)
    and reports the same way. Use it after every edit of a .b file.
    Say a file compiles only when its latest compile said status: compiled;
    if you stop with it failing, say it does not compile, and why.

  LIMBO, NOT C
    A comment begins with # and runs to the end of the line: // and /* */
    are not comments.  Declarations are name: type, and := declares and
    assigns.

  CHANGING A FILE YOU HAVE
    For a change to an existing file (rename something, add a comment or a
    line, fix a compiler error), edit the file with the edit tool, then
    limbo compile it.  Authoring it again with this tool writes the whole
    file anew, and changes what was not asked to be changed.

  WHY THIS TOOL EXISTS
    A new file is written by a Limbo-trained model when one is configured
    (/lib/veltro/limbo-model), else by the session's model given Limbo's
    rules and a whole example program; either way it is compiled before it
    is returned.  Editing a file you have is yours to do (above); what you
    may write is set by your namespace.

  EXAMPLES IN THIS DOCUMENT ARE DOCUMENTATION. Never copy an example's
  argument text as your own tool call. Construct args from the user's
  actual request.
