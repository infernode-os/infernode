# tools/pi-bootfw-manifest.txt -- the Raspberry Pi boot firmware a card
# image carries, pinned by commit and SHA256.  Read by tools/pi-firmware.sh
# (--manifest), which tools/mkpiimage.sh runs.
#
# Format: tools/pi-firmware-manifest.txt's.
#     commit <sha1 of raspberrypi/firmware>
#     file <name> <sha256> <bytes> <licence> <revision URL>
#
# WHAT THESE ARE
#
# The VideoCore firmware that boots a Pi before any ARM code runs, and
# loads the kernel named in config.txt.  A Pi 3B+ wants bootcode.bin,
# start.elf and fixup.dat; a Pi 4B boots from its EEPROM and wants
# start4.elf, fixup4.dat and its device tree (the kernel reads no device
# tree -- it asks the mailbox -- but the firmware wants the file there).
# tools/mkpiimage.sh puts on each card the ones its board needs.
#
# WHY THEY MAY BE IN A RELEASE AND THE RADIO'S MAY NOT
#
# LICENCE.broadcom permits redistribution in binary form, unmodified,
# for running a Raspberry Pi, provided the notice goes with it: so the
# card images carry it beside them.  That is a different licence from
# the CYW43455 radio firmware's (tools/pi-firmware-manifest.txt), which
# never goes in a release.  Neither is committed to this tree.
#
# REPINNING
#
# As tools/pi-firmware-manifest.txt says: change the commit and the
# URLs, run tools/pi-firmware.sh --manifest this-file into a scratch
# directory, and take the hashes from a download you made yourself.
#
# Pinned: raspberrypi/firmware tag 1.20260915.
