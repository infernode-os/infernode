# tools/pi-firmware-manifest.txt -- the CYW43455 firmware the Pi 3B+ kernel
# uploads at boot, pinned by commit and SHA256.  Read by tools/pi-firmware.sh.
#
# Format: 'key value' lines; anything else is a comment.
#     commit <sha1 of RPi-Distro/firmware-nonfree>
#     file <name on the card> <sha256> <bytes> <licence> <revision URL>
# Every URL must name the commit; the tool refuses a manifest where one
# file has floated to a different revision.
#
# WHY THESE FILES ARE NOT IN THE TREE, AND ARE IN ONLY ONE RELEASE
#
# The .bin and .clm_blob are Cypress Semiconductor's, distributed under
# the "CYPRESS WIRELESS CONNECTIVITY DEVICES DRIVER END USER LICENSE
# AGREEMENT" (debian/copyright names it binary-redist-Cypress; its text
# is os/bcm/card/LICENCE.cypress): reproduction and distribution in
# object form, unmodified, "solely for use in connection with Cypress
# integrated circuit products".
#
# Not in the tree: it is not MIT and cannot be re-licensed by us, and
# whatever is placed in the tree's runtime directories goes into every
# release (docs/DESIGN-PRINCIPLES.md, "Placement is shipping").  So the
# blobs are never committed; .gitignore refuses the filenames as a
# second guard, and this manifest plus the fetch tool are the whole of
# what the tree carries.
#
# Not in the hosted releases -- the tarballs, the .app, the .zip: they
# run on computers with no Cypress part, which is outside the licence's
# purpose.
#
# In the Raspberry Pi card images (tools/mkpiimage.sh, release.yml's
# raspberry-pi job), under firmware/ with LICENCE.cypress beside them:
# a card for a Pi 3B+ or 4B is for a board whose radio IS the Cypress
# CYW43455, which is the licence's purpose, as Raspberry Pi OS and
# Debian ship them.  The driver reads them from /n/dos/firmware; a card
# made by hand gets them from tools/pi-firmware.sh.  The radio's
# Bluetooth patch, under the same licence from another repository, has
# its own manifest (tools/pi-btfw-manifest.txt) and takes this road too.
#
# The NVRAM .txt is the board's radio calibration.  In linux-firmware
# the same file (brcm/brcmfmac43455-sdio.raspberrypi,3-model-b-plus.txt)
# is listed under "Licence: GPLv2" in WHENCE; in RPi-Distro's packaging
# every debian/config/brcm80211/*/*43455* path is under the Cypress
# stanza.  Either way it is not MIT, so it takes the same route as the
# blobs; it is plain text, its own source, should GPLv2 be the licence
# that applies.
#
# WHICH BUILD
#
# Raspberry Pi ships two tunings of the 43455 image.  'standard' is the
# one with roaming (802.11k/v/r), DFS channels, auto channel selection
# and antenna diversity; 'minimal' trades those for more clients in AP
# mode (debian/config/brcm80211/cypress/README.txt).  This port is a
# client, so 'standard'.  The image identifies itself, once uploaded,
# as 43455c0-roml Version 7.45.265 (28bca26 CY) FWID 01-b677b91b, dated
# 2023-08-29; the kernel prints that 'ver' string when the dongle comes
# up, which is how a board test confirms which blob it ran.
#
# The names on the card are the ones Richard Miller's ether4330 firmware
# table looks up for chip 0x4345 rev 6, which is why cyfmac43455-sdio-
# standard.bin is installed as brcmfmac43455-sdio.bin.
#
# THE NVRAM PATH
#
# At this commit debian/config/brcm80211/brcm/brcmfmac43455-sdio.raspberrypi,
# 3-model-b-plus.txt is a git symlink to brcmfmac43455-sdio.txt beside it
# (the raw endpoint serves the 22-byte link target for the former, the
# contents API resolves it to the 2074-byte file).  The URL below is the
# link target, so a plain fetch gets the calibration data and not the
# link text.
#
# REPINNING
#
# To move to a newer commit: change the commit line and the URLs, run
# tools/pi-firmware.sh into a scratch directory (it will refuse on the
# old hashes), take the hashes it prints as 'got', and put them here in
# the same commit.  Never take a hash from anywhere but a download you
# performed at the commit you are pinning.
#
